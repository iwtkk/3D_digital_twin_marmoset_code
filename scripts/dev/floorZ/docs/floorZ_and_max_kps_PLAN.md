# floorZ_and_max_kps — 天井突き抜けを直す垂直補正（方針）

最終更新: 2026-06-10
ステータス: **方針確定・未実装**

現行手法（`scripts/dev/floorZ/`）の天井アンカーを、体の上端で取り直して
「天井付近で上半身がメッシュを突き抜ける」問題を解消するための設計メモ。

---

## 1. 背景：何が問題か

現行手法 `floorZ`（= `scripts/dev/floorZ/affine_pkl_csv/pkl_to_corrected_csv.py`）は、
**各フレームの `min(wrist/ankle)` の bZ 分布**を KDE にかけてピークを検出し、
床・足場・棒・天井の物理高さ `PHYSICAL_HEIGHTS_M = [0.7337, 1.0179, 1.3035, 1.5016]` に
affine `bZ_corrected = a·bZ + b` で合わせている（詳細は
`scripts/dev/floorZ/affine_pkl_csv/KDE_INPUT_DISTRIBUTION.md`）。

### 天井での破綻

`min(wrist/ankle)` は「最も低い肢端＝接地点」を測る集約で、
個体が**上に乗る**床・足場・棒では正しい。しかし**天井はぶら下がる／張り付く**ため関係が反転し、
`min` は天井をつかむ手ではなく**下に垂れた肢**を拾う。

→ 検出される「天井ピーク」が真の天井より低く出る
→ それを 1.5016 m に引き上げようとして affine の傾き a が過大になる
→ 天井付近の上半身（頭・背・肩）が **1.5016 を超えて突き抜ける**。

つまり「接地点を面に合わせる」という前提が、天井だけ成立しない。

---

## 2. 決定事項（この方針で確定）

| 論点 | 決定 |
|---|---|
| 天井アンカーに使う量 | **全キーポイントの `max`**（各フレームで一番高い体の点 = 体上端） |
| 1.5016 m の扱い | **超えてはいけない上限**。体上端がこの面を越えないように合わせる |
| 天井に来ないセッション | **従来通り**（`offset_only` / `no_peaks` 等のフォールバックは変更しない） |
| この方法でダメなら | 別案を模索する（§5 参照） |

床・足場・棒の 3 アンカーは **floorZ と完全に同じ**（`min(wrist/ankle)` の KDE ピーク）。
**変更は天井アンカーだけ。**

---

## 3. 提案手法の設計

### 入力分布（2 系統を併用）

| 用途 | 量 | 集約 | 対象 KP |
|---|---|---|---|
| 床・足場・棒（下3点） | bZ | `min` | wrist L/R, ankle L/R（従来通り） |
| 天井（上1点） | bZ | `max` | **全キーポイント** |

- 下3点: `min(wrist/ankle)` 分布 → KDE → ピーク（floorZ と同一処理）。
- 天井: **全 KP の `max(bZ)` per frame** 分布 → KDE → **最上ピーク**を天井アンカー（measured）に採用。
  ターゲットは物理天井 1.5016 m。

### アンカーの組み立てと affine

1. 下3点の (measured=min ピーク, target=物理高さ) を Hungarian で対応付け（floorZ と同じ）。
2. 天井の (measured=max ピーク最上, target=1.5016) を 4 番目のアンカーとして追加。
3. 4 ペアで 1 本の affine を最小二乗フィット（線形のまま）。
   - measured を target に写すだけなので、下3点が min 基準・天井が max 基準でも
     線形フィットとして矛盾しない。
   - これで「体上端がちょうど天井に乗る」＝上半身が突き抜けない。

### 「超えてはいけない上限」の担保

affine は全 KP に一様適用される。体上端ピークを 1.5016 に合わせると、
天井姿勢の代表点が天井に乗る。さらに安全網として（採用は要検討）:

- 補正後に `max(bZ) > 1.5016` のフレームが残る場合に備え、上限クリップ／フレーム押下げを
  **オプション**で用意（§5-D）。まずはクリップ無しで突き抜けが消えるかを評価する。

### 天井フレームの事前選別は不要（循環回避）

「どこが天井か」は補正前に未知だが、**全 KP max 分布の最上ピーク**をそのまま天井アンカーに
使えば、フレームを事前に切り分ける必要がない。天井に滞在した時間が、その最上ピークを形成する。

→ 最上ピークが立たない（天井に来ない）セッションは天井アンカー無し＝**従来フォールバック**に流す。

## 4. floorZ からの差分（実装の見取り図）

- 流用: 回転・グローバル変換・`detect_peaks_kde`・`fit_affine`・CLI・出力形式は floorZ を踏襲。
- 追加: 全 KP の `max(bZ)` per frame を作る処理と、その最上ピークを天井アンカーに差し込む分岐。
- 変更: `fit_affine` 相当に「天井ターゲット 1.5016 を max ピークで固定」する経路を足す。
- 不変: 下3点ロジック・フォールバック・パラメータ（`KDE_BW` 等）は据え置き。

実装ファイルは本ディレクトリ `scripts/dev/floorZ_and_max_kps/` に新規作成（floorZ は触らない）。

---

## 5. うまくいかない場合の代替案（順に検討）

| 案 | 内容 | 使いどころ |
|---|---|---|
| A（本命） | 全 KP max の上ピークを天井アンカーにして affine 再フィット | まずこれを評価 |
| B | 天井アンカーを外し床・足場・棒の3点だけで affine | max ピークが不安定なセッションが多い場合 |
| C | 天井は集約を `max(wrist/ankle)`（つかむ手）に | 背中より手が確実に上なら軽い修正で済む |
| D | 補正後に体上端 > 天井をクリップ/フレーム押下げ | A の安全網（対症療法、姿勢は歪む） |

A がダメなら、まず「体上端の定義（全 KP max が外れ値に弱くないか）」と
「天井アンカーを affine に入れるか上限キャップに留めるか」を見直す。

## 6. 検証計画

1. **機序確認**: 天井に来るセッション（例 `cj425_20210427_120000` full_affine）で、
   `min(wrist/ankle)` ピークと `max(all KP)` ピークが天井付近でどれだけズレるか可視化。
2. **before/after**: 補正後に体上端 `max(bZ)` が 1.5016 を超えるフレーム率を before/after で比較。
3. **回帰の健全性**: 下3点 min・天井 max の混在アンカーで a, b が floorZ と大きく乖離しないか
   （全 222 session の slope/intercept 分布で確認）。
4. **非天井セッションが無影響**であること（フォールバック経路を通る）。
