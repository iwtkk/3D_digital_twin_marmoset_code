# 垂直 affine 補正の「線形回帰」は何をしているのか

対象コード: `pkl_to_corrected_csv.py` の `fit_affine()`（192〜220 行目）
図: [`affine_regression_explained.png`](affine_regression_explained.png)（実データ `cj425_20210428_090000`）

---

## 一言でいうと

> **「いま見えている高さ（x）」と「本当はあるべき高さ（y）」のペアを
> 床・足場・棒・天井の最大 4 個つくり、その点に最小二乗で直線を 1 本引いている。**

引いた直線 `y = a·x + b` が、そのまま**補正の変換式**になる。
任意の補正前 bZ を x に入れれば、補正後 bZ が y として出てくる。

```python
bZ_corrected = a * bZ + b   # 306-308行。a=slope, b=intercept
```

---

## 何に対して回帰しているのか（x と y の正体）

回帰に渡すのは、たった 2〜4 個の点。各点は**1 つのプラットフォームに対応**する。

| 記号 | 中身 | コード |
|---|---|---|
| **x** = `mp_v` | そのプラットフォームが**いま見えている高さ**（補正前 bZ で検出した KDE ピーク） | `peaks` |
| **y** = `mh_v` | そのプラットフォームの**あるべき物理高さ**（実測値） | `PHYSICAL_HEIGHTS_M` |

```python
slope, intercept = np.polyfit(mp_v, mh_v, 1)   # 1次フィット = 直線
#                              ↑x    ↑y
```

- `x`（横軸）= グローバル変換後の bZ 空間で、floor KP（手首・足首）高さ分布を KDE にかけて
  見つけた**山の位置**。「床・足場・棒・天井が、補正前は何 m に見えているか」。
- `y`（縦軸）= その山が対応する**物理高さ** `[0.7337, 1.0179, 1.3035, 1.5016]` m。
  どのピークがどの物理高さかは Hungarian マッチング（`linear_sum_assignment`）で決める。

つまり回帰の入力は「**(現在の見え方, 正解の高さ)** の対応表」。

### 実データの対応表（`cj425_20210428_090000`, 4 ピーク）

| プラットフォーム | x = 検出ピーク (m) | y = 物理高さ (m) | ずれ x−y |
|---|---|---|---|
| 床 floor | 0.7704 | 0.7337 | +37 mm |
| 足場 low perch | 1.0614 | 1.0179 | +44 mm |
| 棒 high perch | 1.3499 | 1.3035 | +46 mm |
| 天井 ceiling | 1.5317 | 1.5016 | +30 mm |

→ どの高さも一様に 30〜46mm ほど高く見えている。この「ズレの規則性」を直線で捉える。

---

## 「いい感じの直線」とは何か（図の右パネル）

![regression](affine_regression_explained.png)

### 右パネル B が回帰そのもの

- 4 つの丸 = 上の対応表の (x, y) 点。
- **赤い実線** = `np.polyfit(x, y, 1)` で求めた最小二乗の直線 `y = 1.0045·x − 0.0444`。
  4 点からの縦方向の二乗誤差合計が最小になるよう引かれる。これが「いい感じの直線」。
- **灰色の点線 `y = x`** = 「補正不要」の基準線。点がこの線に乗っていれば
  見え方=物理高さ で、すでに正しい。

**点が `y=x` から下にずれている** ＝ 実際の高さより高く見えている、という意味。
赤線が `y=x` より下を通ることで、その分を引き戻すのが補正になる。

### 左パネル A は x の作り方

- 灰色の山 = floor KP の補正前 bZ 分布（KDE）。
- **実線** = 検出したピーク（= 右パネルの x 座標）。
- **破線** = 物理高さの目標（= 右パネルの y 座標）。
- **矢印** = 実線（現在）→ 破線（目標）へ動かしたい量。この「ズレ集」を直線化したものが回帰。

---

## a と b の意味

`y = a·x + b` の 2 パラメータが、2 種類の誤差をそれぞれ吸収する。

| パラメータ | 名前 | 直すもの | 理想値 |
|---|---|---|---|
| `a` (slope) | 傾き | **スケール誤差**（高い所ほど大きくズレる伸縮） | 1.0 |
| `b` (intercept) | 切片 | **オフセット誤差**（全体が一律に浮く/沈む平行移動） | 0.0 |

- `a=1, b=0` なら赤線 = `y=x` で、補正は何もしない（恒等変換）。
- 単なる平行移動（`a=1` 固定の offset_only）では、高さによって違う伸縮を直せない。
  **複数の既知高さ**があってはじめて `a`（傾き）も決められる ＝ これが affine 回帰を使う理由。

この session は `a=1.0045`（ほぼ伸縮なし）, `b=−0.0444 m`（全体を約 44mm 下げる）。

---

## 数値で 1 フレーム追ってみる

棒（high perch）にいる瞬間、補正前 bZ = 1.3499 m だったとする。

```
bZ_corrected = a * bZ + b
             = 1.0045 * 1.3499 + (-0.0444)
             = 1.3560 - 0.0444
             ≈ 1.3035 m   ← 棒の物理高さにぴったり
```

床（0.7704 m）なら `1.0045*0.7704 − 0.0444 ≈ 0.7297 m`（物理 0.7337 とほぼ一致）。
こうして**全フレームの bZ が物理高さ基準に揃う**。回帰は「この 1 本の直線を決める」作業に他ならない。

---

## ピーク数が 4 未満のとき（回帰の縮退）

セッションによっては個体が全プラットフォームを訪れず、点が 4 個揃わない
（`vertical_correction_status.md`：4 ピークは全体の 14% のみ）。点が少ないと直線は引けない／不安定なので段階的にフォールバックする。

| 有効点数 | 直線の決め方 | status |
|---|---|---|
| 4 | 4 点で最小二乗フィット | `full_affine` |
| 2〜3 | あるピークだけで最小二乗フィット | `partial_affine_Npeaks` |
| 1 | 傾き `a=1` 固定、`b=物理高さ−ピーク`（平行移動だけ） | `offset_only` |
| 0 | `a=1, b=0`（何もしない） | `no_peaks` |

点が 1 個では傾きが決まらない（直線は無数に引ける）ので、`a=1` に固定して切片だけ合わせる。
このとき回帰は実質「平行移動」に退化する。

---

## まとめ

- 回帰の **x = 検出ピーク（いまの見え方）**、**y = 物理高さ（正解）**。
- 床〜天井の (x, y) 点に**最小二乗で 1 本の直線**を当てる。
- その直線 `y = a·x + b` が補正式そのもの。`a` がスケール、`b` がオフセットを直す。
- `y=x`（恒等）からのズレ＝ session 固有の系統誤差で、それを直線で打ち消している。
